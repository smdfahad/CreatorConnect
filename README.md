# CreatorConnect

CreatorConnect connects local businesses that want promotion with YouTubers who want to promote those businesses.

## Setup

1. Install dependencies with `npm install`.
2. Copy `.env.example` to `.env.local` and set `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY`. The browser app must only use a publishable/anon key; never put a service-role key in Vite environment variables.
3. In the Supabase SQL Editor, run [`supabase/migrations/20261012000000_auth_profiles.sql`](supabase/migrations/20261012000000_auth_profiles.sql). This creates the private account profile table, signup trigger, immutable role enforcement, and own-profile RLS policies. It also safely backfills existing Auth users whose saved role is `business_owner` or `creator`; existing profile rows are left untouched. If this migration was already run before the backfill was added, run the updated SQL file again. If you also apply [`supabase/schema.sql`](supabase/schema.sql) for other existing app features, apply the auth migration after it so the auth-only signup trigger is the active one.
4. Run [`supabase/migrations/20261012010000_business_profiles.sql`](supabase/migrations/20261012010000_business_profiles.sql) in the Supabase SQL Editor. It adds the owner-linked business profile table, owner-only RLS, and a public view that excludes owner names, addresses, and contact details. Existing `businesses` rows without an authenticated owner remain unassigned; the migration does not guess or invent ownership.
5. Run [`supabase/migrations/20261012020000_promotion_listings.sql`](supabase/migrations/20261012020000_promotion_listings.sql) in the Supabase SQL Editor after the business-profile migration. It creates owner-linked listings, allows public reads of published listings only, and keeps drafts and other non-published listings private to their business owner.
6. Run [`supabase/migrations/20261012030000_creator_profiles_and_discovery.sql`](supabase/migrations/20261012030000_creator_profiles_and_discovery.sql) in the Supabase SQL Editor after the promotion-listings migration. It creates private owner-only creator profiles, creator-only saved opportunities with duplicate protection, a sanitized published-listings view, and the server-side discovery function.
7. Run [`supabase/migrations/20261012040000_creator_offers.sql`](supabase/migrations/20261012040000_creator_offers.sql) in the Supabase SQL Editor after the creator profile and opportunity-discovery migration. It creates secure creator offers and immutable negotiation history, with role-checked RPCs and party-scoped RLS.
8. Run [`supabase/migrations/20261012050000_collaboration_management.sql`](supabase/migrations/20261012050000_collaboration_management.sql) after the creator offers migration. It adds offer-linked collaborations, participant confirmation, private conversations and messages, and persistent notifications. Both parties must confirm before a collaboration is marked confirmed.
9. Run [`supabase/migrations/20261012060000_creator_discovery_profiles.sql`](supabase/migrations/20261012060000_creator_discovery_profiles.sql) after the collaboration-management migration. It adds creator state and optional profile-image fields plus a sanitized creator-discovery view readable only by authenticated users. The underlying creator profile table remains private and keeps its owner-only RLS policies.
10. Run [`supabase/migrations/20261012070000_creator_profile_requests.sql`](supabase/migrations/20261012070000_creator_profile_requests.sql) after the creator-discovery migration. It enables authenticated business owners to submit deduplicated requests to registered creators by auth user ID; requests are visible to both participants and creators can accept or reject them. This flow records in-app requests and notifications; it does not send email.
11. Run [`supabase/migrations/20261013000000_profile_image_storage.sql`](supabase/migrations/20261013000000_profile_image_storage.sql) after the creator-profile migrations. It creates the public image bucket for creator and business profile uploads, restricts uploads and changes to the authenticated account's own folder, and accepts JPEG, PNG, and WebP images up to 5 MB.
12. In Supabase Authentication → URL Configuration, set the local Site URL to `http://localhost:5174` and allow that URL as a redirect URL. Add your deployed app URL before deploying.
13. Keep email confirmation enabled if required for your project. Users must verify their email before they can sign in when confirmation is enabled.
14. Run `npm run dev` from this folder, or from the workspace root.

## Application flows

- Email/password signup and login use Supabase Auth; sessions are restored after refresh.
- Creator discovery shows local demo cards first, followed by registered profiles from the authenticated-only `public.public_creator_profiles` view on the same front page. The signed-in creator's own saved profile is included first among registered creators, even if the discovery view omits it; discovery query errors remain visible. The view exposes only creator discovery details; profile reads and edits remain owner-scoped on `creator_profiles`. One search box searches creator name, channel, niche, biography, city, and state; the separate sort control orders results.
- Signup supports Business Owner and YouTuber / Creator roles. A database trigger validates the selected role and creates only the account profile; it does not create a business listing or creator listing.
- Users can request a password-reset link and set a new password from the secure recovery link.
- Application profiles contain account details only. Passwords remain managed by Supabase Auth, and RLS restricts profile reads and updates to the owner. The role is assigned at signup and cannot be changed from the profile API.
- Business owners can create, view, and edit one owner-linked business profile. Public business details are available through `public.public_business_profiles` only when the owner explicitly marks the profile public; owner name, address, and contact information are not included in that view.
- Business owners can create listings as drafts or publish them, edit them, pause and resume them, or close them. Published listings are readable publicly; draft, paused, and closed listings remain visible only to their owner. Closed listings cannot be reopened. Listing operations require the promotion-listings migration above; this phase does not add offers or negotiation.
- Creators can create and edit their own channel profile, including public discovery details such as name, channel, city and state, audience metrics, pricing, availability, and an optional photo URL. The full creator profile remains private to its owner; signed-in users discover the sanitized `public_creator_profiles` view. The Discover Opportunities feed uses the published-listings database view and server-side filters, best-match ranking (when a creator profile exists), and bounded pagination. Creators can save and remove published opportunities; duplicate saves are prevented by a database unique constraint. The profile's travel distance is a preference only: no coordinates or other precise location data are collected, and discovery filters by city.
- Creators and business owners can upload profile images from a camera or choose images from a gallery/files. Uploads use the authenticated user's own folder in Supabase Storage; image files are JPEG, PNG, or WebP up to 5 MB and their public image URLs are saved in the existing profile fields. Uploaded images are publicly viewable; private business contact fields remain private.
- Business owners can request collaboration with a registered creator from the front-page card. Requests are stored securely against the creator's authenticated user ID, appear in both participants' request dashboards, and creators can accept or reject them. The request flow does not claim to send email.
- Creators can submit priced offers with messages, proposed deliverables, and an optional schedule on published listings. Business owners can review the offering creator's profile, accept, reject, or counter. Creators can accept or reject a counteroffer, withdraw an offer awaiting a business response, and submit a new offer after rejection or withdrawal. Every change is recorded in an append-only negotiation history, and only the relevant party can perform each action. An accepted offer means the current price and terms were accepted by both parties; it does not automatically create or confirm a collaboration.
- For mutually accepted offers, either participant can begin collaboration confirmation. The second participant must confirm the same agreed date; the campaign is marked confirmed only after both confirmations. Both participants can view the same agreed business, creator, listing, price, date, and deliverables. Participants can update valid campaign statuses, open a private collaboration conversation, and exchange messages. RLS and database functions restrict records and changes to the relevant participants. Upcoming campaign notifications for the next three days are generated when a participant loads the app; notifications persist in Supabase and can be marked read.
- CreatorConnect does not process or record payments. Marking a collaboration completed is a participant status update, not evidence of payment or independent verification that campaign work was delivered.
- Business profile photographs and logos use image URLs. File upload storage is not configured in this phase.
